## Goal
Put the database under Alembic. The first revision reproduces today's schema exactly, so
reviewers only have to diff one new migration (0002, in T1.4) against v1.

## Contract
- `split_sql(text: str) -> list[str]` in `northvaine/core/sqlsplit.py` (PLAN.md).
- `migrated_url` sync fixture in `tests/db/conftest.py` (PLAN.md). It yields a str URL of a
  database at `head`.
- `env.py` modes:
  - offline: `context.configure(dialect_name="postgresql", literal_binds=True, ...)`, with no
    URL and no settings read;
  - online: the URL comes from `-x url=...` or `config.attributes["url"]` if given, otherwise
    `require_database_url()`. It is normalized with `northvaine.core.db.normalize_database_url`,
    and `connect_args` are passed to `async_engine_from_config(..., poolclass=NullPool)` via
    `asyncio.run`.

## Acceptance criteria
- [ ] `migrations/sql/0001_v1_baseline.sql` is byte-identical to `schema.sql` at e141b6d.
  `test_migrations_offline.py` asserts its sha256, computed after normalizing CRLF to LF.
- [ ] The `split_sql` tests in `tests/core/test_sqlsplit.py`:
  - the baseline file splits into exactly 2 + 25 + 1 statements (2 extensions, 25 tables, 1

  - semicolons inside comments (line 5) do not split;
  - quoted `';'`, `"a;b"` and `$$...;...$$` do not split;
  - for every statement, `sa.text(stmt).compile().params == {}` (no bind parameters).
- [ ] Revision `0001` (down_revision None) reads the frozen file with `encoding="utf-8"` and
  runs one `op.execute(sa.text(stmt))` per statement. Its downgrade drops every v1 table in
  reverse dependency order and **leaves the extensions in place**.
- [ ] `uv run alembic upgrade head --sql` exits 0 with DATABASE_URL unset and no `.env`.
  `test_migrations_offline.py` runs it through `alembic.command.upgrade(cfg, "head",

- [ ] `alembic.ini` is ASCII-only, has `script_location = %(here)s/migrations` and

- [ ] `tests/db/conftest.py` `migrated_url` implements both `test_db_isolation` modes,
  derives the per-run database name `nv_test_<uuid4 hex[:12]>`, and skips without

- [ ] Gate passes.

## Notes
- Online multi-statement strings fail with asyncpg, because SQLAlchemy prepares every
  statement. Never pass the whole file to `op.execute`. Do not use the unconfirmed raw
  `run_async` route.
- Online mode depends on `normalize_database_url`, which T1.2 implements in the same wave.
  This ticket only proves offline mode. The online round trip is tested in T1.4 after both
  merge.
- Reading alembic.ini uses the locale encoding (cp1252) on Windows, so keep it ASCII.
- Dropping a per-run database (not a schema) avoids dropping the database-wide `vector`
  extension under other runs.
