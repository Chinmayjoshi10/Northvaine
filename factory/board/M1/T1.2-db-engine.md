## Goal
One correct way to reach Postgres from anywhere in the app, from Alembic and from tests. It
must accept the URLs that hosted providers actually hand out, and create nothing at import.

## Contract
Implement the frozen `northvaine/core/db.py` signatures from PLAN.md. Do not change them.

## Acceptance criteria
- [ ] `normalize_database_url` follows these rules, each proven by a parametrized case in
  `tests/core/test_db.py`:
  - `postgres://` and `postgresql://` (and `postgresql+psycopg://`) become
    `postgresql+asyncpg://`;
  - `sslmode=disable|allow|prefer|require|verify-ca|verify-full` is removed from the query and
    becomes `connect_args["ssl"]` with the same value;
  - with `sslrootcert`, `sslcert` or `sslkey` present, `connect_args["ssl"]` is an
    `ssl.SSLContext` loading those files, with verification on for verify-ca/verify-full and
    hostname checks for verify-full. A missing file raises ConfigError;
  - `sslmode=verify-full` without `sslrootcert` raises ConfigError, which says to set
    sslrootcert. The libpq default root.crt path is not relied on;
  - `channel_binding`, `options`, `target_session_attrs`, `gssencmode` are dropped, with a
    debug log that does not include the URL;
  - `ssl=...` and other keys pass through unchanged;
  - `redact_url` hides the password, and no log record produced in these tests contains the
    password.
- [ ] Importing db.py creates no engine. `get_engine()` builds one lazily. Without a URL
  (`clean_settings`) it raises ConfigError. Called twice, it returns the same object.
- [ ] `create_engine` behaves by pool mode (unit tests inspect `engine.pool` and the dialect
  connect args; no DB needed):
  - with `db_pool_mode="transaction"`: `poolclass=NullPool`, `prepared_statement_cache_size=0`,
    `statement_cache_size=0`, and a `prepared_statement_name_func` producing unique
    `__asyncpg_<uuid>__` names;
  - with `"session"`: the queue pool with `db_pool_size`, `db_max_overflow`,
    `pool_pre_ping=True`.

  A Neon `-pooler` host is treated as transaction mode even if the setting says session. No
  other host-based inference is done.
- [ ] `session_scope` commits on success and rolls back and re-raises on exception.
  `get_db` yields a session. `dispose_engine` disposes and resets the singleton, and is a
  no-op when none exists. Tested with a fake sessionmaker, no DB.
- [ ] `check_database` returns DatabaseStatus from `SHOW server_version`,
  `SHOW server_version_num` and `pg_extension`. `main()` prints the status with
  `redact_url(...)` and returns 0, or prints a readable ConfigError and returns 1 (unit test
  with no URL). `python -m northvaine.core.db` calls `main()`.
- [ ] `tests/db/test_db_live.py` (marked `db`) uses TEST_DATABASE_URL to prove:
  - `check_database` reports `server_version_num >= 150000` and `has_vector` after
    `CREATE EXTENSION IF NOT EXISTS vector`;
  - the running loop class name is logged (expected ProactorEventLoop on Windows);
  - `has_pgcrypto` is reported as information only, not asserted.

  It skips without TEST_DATABASE_URL.
- [ ] The T1.0 contract test still passes. Gate passes.

## Invariants touched
- Never log secrets: URLs are always redacted.
- No network libraries beyond the DB driver. SQLAlchemy and asyncpg are allowed in core.

## Notes
- The TypeError for `channel_binding` is inferred from the pass-through code, not tested
  upstream. Stripping it is safe either way.
- The Nebius transaction pooler's port and format are unconfirmed, so the founder sets
  `DB_POOL_MODE=transaction` explicitly.
- Live tests rely on the conftest dispose fixture to avoid "attached to a different loop"
  errors.
