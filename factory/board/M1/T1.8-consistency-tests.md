## Goal
Make schema drift impossible to miss. schema.sql, the migrations and the Pydantic models must
agree, and the real database must match.

## Contract
`tests/core/ddl_parser.py` is a documented, line-based parser for the DDL subset used here:
- CREATE TABLE with columns, NULL/NOT NULL, PRIMARY KEY and inline CHECK IN;
- ALTER TABLE ADD/DROP/ALTER COLUMN TYPE;
- ADD CONSTRAINT CHECK;
- CREATE VIEW (name only);
- CREATE [UNIQUE] INDEX (name only).

It returns `dict[table, dict[column, ColumnInfo(type, nullable, check_values)]]`, built on
`split_sql`. It adds no new dependency.

## Acceptance criteria
- [ ] `test_ddl_parser.py` gives unit cases for every construct above, including a column with
  an inline comment and a multi-line CHECK.
- [ ] Tests without a DB:
  - the tables and columns (with nullability) parsed from schema.sql equal those obtained by
    replaying the offline-rendered SQL of `alembic upgrade head`;
  - no column of type `vector(N)` remains.
- [ ] More tests without a DB:
  - every `<X>Row` field set equals its table's column set, and Optional matches nullability;
  - every `CHECK (... IN (...))` list equals its StrEnum's values.
- [ ] Without a DB: EventType values equal the 12 level-0 seed labels in migration 0002, which
  equal the SPEC §1 list (parsed from docs/SPEC.md).
- [ ] Adversarial checks without a DB:
  - a temp copy of schema.sql with one extra column makes the schema-vs-migrations
    comparison fail;
  - a model missing a field makes the model check fail.
- [ ] `tests/db/test_schema_live.py` (marked `db`, on `migrated_url`): `information_schema`
  tables, columns and nullability equal the schema.sql parse, the `patterns` view exists, and
  `pg_attribute.atttypmod` shows every vector column as dimensionless.
- [ ] `uv run python scripts/gate.py` passes on a clean checkout with no Postgres.
- [ ] **Milestone sign-off:** `uv run python scripts/tasks.py db-test` passes against the
  founder-provided TEST_DATABASE_URL. The output summary (counts passed, server version, loop
  class) goes in the report. Until then this ticket stays `blocked`, not `done`.

## Invariants touched
- Tests are never weakened to pass.
- No network in default tests. DB tests only run under the `db` marker.

## Notes
If the parser cannot handle a construct, extend the parser and its tests. Do not exclude the
table. The live information_schema check is the authoritative one.
