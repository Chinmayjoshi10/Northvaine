## Goal
The gate catches a broken migration and an industry word in SQL, and it never needs Postgres.

## Contract
`gate.steps() -> list[tuple[str, list[str]]]` and `gate.main() -> int` keep their shape.
`check_invariants` keeps `main() -> int` and gains
`check_sql_banned_terms(files: list[Path], terms: list[str]) -> list[str]`.

## Acceptance criteria
- [ ] The step order is invariants, lint, migrations render, unit tests, golden, frontend.
  The render step is added only when `alembic.ini` exists. It runs
  `python -m alembic upgrade head --sql`, discards stdout, and uses an env copy with
  DATABASE_URL removed. `tests/scripts/test_gate.py` asserts the step list and order, and,
  with a monkeypatched runner, that a failing render fails the gate.
- [ ] Lint covers `northvaine tests scripts migrations` (asserted).
- [ ] Unit tests run with `-m "not live and not db"` (asserted).
- [ ] `check_invariants` scans `schema.sql` and `migrations/**/*.sql|*.py` for banned terms.
  A test with a temp tree containing a banned word in a migration reports a violation. A
  clean tree passes. The real repo passes.
- [ ] Tests cover the existing rules:
  - LLM SDKs only in brain/llm.py;
  - network libs only in sensors/ and brain/llm.py;
  - no sending libraries;
  - the secrets scan.

  Each has one violating and one clean case, and the behaviour is unchanged.
- [ ] `uv run python scripts/gate.py` passes.

## Invariants touched
This ticket enforces them: no industry words (now including SQL), LLM and network
containment, no sending, no secrets.

## Notes
The render must not read `.env`. T1.1's offline env.py uses `dialect_name` only, so removing
DATABASE_URL from the env is extra safety, not a requirement.
