## Goal
Run a client's sensors and turn snippet-only leads into evidence by fetching each lead's own
publisher page safely, so the announcement stream (and the packaging client) has full text to
extract from (D45, D59).

## Contract
As frozen in PLAN.md:
- `shift_queries(queries, as_of)`: each query with both dates keeps its length and ends at
  `as_of`; a query with only `published_to` moves it to `as_of`; queries without dates unchanged.
  Pure; returns copies.
- `strip_contacts(text)`: emails and phone numbers (same patterns as the sensor recorder, copied
  into this module) replaced by `[contact removed]`; idempotent.
- `LivePageFetcher(client=None, resolver=None, settings=None)`: `RobotsCache.ensure_allowed`, then
  `safe_fetch`, then the website content-type rule, then `html_to_text`, then `strip_contacts`.
  Never raises for one page: refusals become `UpgradedPage.refused` (`robots`, `denied`,
  `http_<status>`, `content_type`, `error`).
- `RecordedPageFetcher(pages)`: returns the recorded page for a URL; unknown URL raises
  `sensors.replay.ReplayMismatch` (never fetches).
- `upgraded_document(page, lead)`: `None` when refused or empty text; else an `EvidenceDocument`
  with `source_name="website"`, `url=final_url`, `available_at=fetched_at`, deterministic id from
  the content hash, `meta={"upgraded_from": lead.url, "lead_source": lead.source_name,
  "claimed_published_on": lead.meta.get("published_on")}`.
- `discover(spec, queries, *, http, fetcher, settings)`: for each sensor name in `queries`, build
  the sensor with `get_sensor(name, client=http)` and run every query; convert results with
  `evidence_document_from_sensor`; de-duplicate by content hash then URL; documents whose
  eligibility is `lead` and that have an http(s) URL are upgraded through `fetcher`, at most
  `radar_max_lead_upgrades`, in result order; lead documents themselves are kept out of
  `documents` but counted in `leads`. Sensor errors become notes, not crashes.

## Acceptance criteria
- [ ] `tests/radar/test_discover.py`: `shift_queries` keeps lengths and is pure.
- [ ] `strip_contacts` removes an email and two phone formats and leaves other digits (a year, a
      price) untouched; applying it twice changes nothing.
- [ ] Live fetcher with a mock transport (`httpx.MockTransport`) and a fake resolver: robots
      disallow -> `refused="robots"`, no page request made; a denied host (from
      `fetch_deny_hosts`) -> `refused="denied"`; 404 -> `http_404`; PDF content type ->
      `content_type`; an HTML page with an injected instruction and an email comes back as text
      with the email removed and the instruction kept as plain text (data, not followed).
- [ ] `discover` over the recorded packaging Tavily fixture with a `RecordedPageFetcher` of
      synthetic pages: every snippet lead is offered for upgrade, upgraded documents are
      `full_text` by `is_evidence_document`, and the cap is respected.
- [ ] `RecordedPageFetcher` raises `ReplayMismatch` for an unrecorded URL; no network in tests.
- [ ] `tasks.py gate` green.

## Invariants touched
- Rule #9: the deny list (LinkedIn and others) and robots.txt are enforced before any page fetch.
- Rule #7: fetched text is data; it is only ever passed to the LLM fenced (by the M4 extractor).
- Personal data: contact details are removed before a document exists; nothing is stored raw.
- Point-in-time: upgraded documents get `available_at = fetched_at` (D37).
