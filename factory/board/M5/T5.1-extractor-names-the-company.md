## Goal
Fix the riskiest step first: M4's recorded extractions never named the company, so no extracted
event had a subject. Make the extractor name the organisation each claim is about, in a quote
that contains the name, so `ground_event` keeps it (D50). Prove it on real recordings before any
other M5 spend (Checkpoint A, PLAN.md).

## Contract
- `ExtractedClaim`: `subject_name: str | None`, `subject_country: str | None`,
  `subject_role: str | None` become **required** (no default) so the strict schema lists them in
  `required` with `anyOf [string, null]`.
- `ExtractedEvent`: `subject_name`, `date_text`, `group_hint`, `concept_label`, `concept_hint`
  become required-nullable the same way. `slots` and `claim_indices` unchanged.
- `evidence_extract.v2.md` (new; v1 stays for history): the same fenced variables as v1, plus:
  - "subject_name is the organisation the claim is about, written exactly as in the document.
    Choose a source_quote that contains that name. If the document does not name it, null."
  - roles as short snake_case words describing the organisation's part in the fact (e.g. buyer,
    winner, investor, operator, publisher), never a person's job title; never name a person as a
    subject (persons -> null).
  - "Use an event type only if its description fits what the quote says happened. If none fits,
    put no event." Plus one generic rule: a company investing in or opening its own site is not a
    contract award.
  - No industry words (rule #1; the prompt is scanned by `check_invariants`).
- `extract()` signature and output types unchanged; `load_prompt("evidence_extract")` picks v2.
