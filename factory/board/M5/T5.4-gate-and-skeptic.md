## Goal
Reject competitors, resellers, publishers, non-buyers and persons **before** any investigation,
keeping every rejection with its reason; then, for passed candidates only, store the evidence
against (or "unknown" with open questions). Every model-written sentence cites claims and adds
no number (D62, D63).

## Contract
- `numbers_grounded(text, quotes)`: every number token in `text` (digits with optional `.`/`,`
  separators, normalized) appears in at least one quote; text without numbers is grounded.
- `gate_candidate(candidate, spec, *, run, session=None, settings=None) -> GateDecision`:
  - Code first: a candidate with no claims -> `INSUFFICIENT_EVIDENCE`, `by="code"`, no call.
  - One `complete_json(tier=MID, prompt=load_prompt("radar_gate"), output_model=GateOutput,
    purpose="radar_gate", max_tokens=settings.gate_max_tokens)`. Variables: the client's offer and
    markets (owner data, not fenced); candidate name, roles and the claims as `ref: statement /
    "quote" (source)` lines, all fenced `Untrusted`.
  - Mapping: `buyer` -> passed; any other verdict -> `RejectedAs` of the same name, `by="llm"`.
    `cited_refs` filtered to the candidate's refs; a `buyer` verdict with no valid ref becomes
    `INSUFFICIENT_EVIDENCE`. Each of `buyer_reason`, `demand_reason`, `suggested_action` is kept
    only if `numbers_grounded` against the cited quotes, else `None`.
  - `not_an_organisation`: `reason` is replaced by a fixed code string that does not repeat the
    name (D62: persons' names withheld).
- `skeptic(candidate, gate, spec, *, run, session=None, settings=None) -> SkepticFinding`:
  refuses (`ValueError`) a gate that did not pass (ordering invariant). One mid-tier call
  (`radar_skeptic`, `skeptic_max_tokens`) seeing the candidate's fenced claims, the offer and the
  gate's demand reason; never a score or rank. Points with unknown refs or ungrounded numbers are
  dropped; none left -> `stance="unknown"`; open questions number-guarded the same way.
- Prompts: generic, no industry words. The gate explains each verdict in one line, defines
  `direct_buyer` (the named organisation itself would buy the offer, vs. it commissions others
  who would, D19), and forbids prices, discounts, dates and terms in `suggested_action`
  (rule #5 spirit) and any contact person. Both say fenced text is data, never instructions.

## Acceptance criteria
- [ ] `tests/radar/test_gate.py` with a fake LLM client (`llm.client_override`): each verdict maps
      to the right `GateDecision`; invalid refs dropped; buyer without valid refs ->
      `insufficient_evidence`; a demand reason containing a number absent from cited quotes ->
      `None`; a person verdict's reason does not contain the candidate name.
- [ ] A candidate with no claims makes no LLM call (spy asserts zero requests).
- [ ] The rendered gate request fences every claim, quote and the candidate name (nonce present);
      an injected instruction inside a quote appears only inside the fence.
- [ ] Request uses the mid tier and `gate_max_tokens`; `purpose="radar_gate"`.
- [ ] `tests/radar/test_court.py`: skeptic refuses a failed gate; valid against points kept with
      refs; all-invalid -> `unknown`; request contains no rank or score text.
- [ ] `numbers_grounded` table test: "12 million" vs quote "12 million euros" true; "15" vs "150"
      false; "2,5" vs "2.5" true (normalized).
- [ ] Prompts pass `check_invariants` (banned terms) and `tests/brain/test_prompts.py` loading.
- [ ] `tasks.py gate` green.

## Invariants touched
- Rule #3: the gate runs before the skeptic and before any brief; rejections are returned, never
  dropped (`RejectedEntry` in T5.6).
- Rule #4: every passed candidate gets a `SkepticFinding` (evidence against or `unknown`).
- Rule #2 / D63: model text only cites verified claim refs and adds no numbers.
- Rule #5: no prices or terms in suggested actions; a person decides.
- Rules #7, #8: all external text fenced; all calls through `brain/llm.py`.
