## Goal
Land every shape the M5 radar shares, so wave 1 can build entities, discover, gate/skeptic and
brief in parallel without touching each other's files. No behaviour beyond the items marked impl.

## Contract
Exactly the "Frozen contracts (T5.0)" section of `PLAN.md`:
- `northvaine/radar/models.py` (impl): `RadarStream`, `stream_is_enumerable`, `RejectedAs`,
  `ClientSpec`, `load_client_spec`, `CandidateClaim`, `CandidateEvent`, `Candidate`,
  `GateDecision` (validator `passed == (rejected_as is None)`), `AgainstPoint`,
  `SkepticFinding` (validator `stance == "against"` iff `against`), `RankedEntry`,
  `RejectedEntry`, `UpgradedPage`, `DiscoverResult`, `RadarRun`. Pydantic v2 on
  `NorthvaineModel`; JSON round-trip (`RadarRun.model_dump_json` / `model_validate_json`).
- `GateOutput` in `radar/gate.py` and `SkepticOutput` (+ its item model) in `radar/court.py`
  (impl): strict-schema-safe shapes, every field required, nullable as `X | None` without a
  default, `cited_refs` maxItems 8, `against` maxItems 4, `open_questions` maxItems 3; no
  docstrings and no `Field(description=...)` on these models (PF1).
- Skeletons with docstrings and `NotImplementedError` bodies: `entities.py`, `discover.py`
  (incl. the `PageFetcher` Protocol, impl, and the two fetcher classes as stubs), `gate.py`,
  `court.py`, `brief.py`, `run.py`, with the signatures in PLAN.md.
- Settings (impl) as listed in PLAN.md, each validated (positive ints, `radar_stream_by_event`
  values are `RadarStream` values, `radar_enumerable_sources` non-empty).
- `check_invariants.py`: new rule — `northvaine/radar/brief.py` and `northvaine/radar/entities.py`
  must not import `northvaine.brain.llm` (directly or `from northvaine.brain import llm`), with a
  planted-violation test.
- `.gitignore`: `reports/radar/` (D66, pending founder Q1).
