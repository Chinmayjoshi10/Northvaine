## Goal
Let every LLM-using test in M4 and later replay real recorded model calls offline, independent of
`.env`, and give the orchestrator one command that records them cheaply and safely.

## Contract
`brain/replay.py` as frozen in PLAN.md: `LlmExchange`, `LlmRecording`, `normalize_body`,
`exchange_key`, `load_recording`/`save_recording`, `ReplayClient`, `RecordingClient`,
`replay_environment`. Uses `llm.client_override` (T4.0) and calls `radar.ledger.build_evidence`
(T4.5, stubbed in this ticket's tests).

## Acceptance criteria
- [ ] `normalize_body` replaces every fence nonce (`-----BEGIN|END <LABEL> DATA <32 hex>-----`) with
      a fixed token; `exchange_key(kind, body)` is sha256 of canonical JSON (sorted keys, no
      whitespace). Two renders of the same prompt and variables give the same key; a one-character
      change in any variable, in `max_tokens` or in the model id changes it. Tested.
- [ ] `ReplayClient(recording)` answers `chat.completions.create(**body)` and
      `embeddings.create(**body)` with objects in the attribute shape `llm.py` reads (duck-typed, no
      SDK import). An unknown request raises `LlmReplayMismatch` naming the prompt version (from the
      rendered front matter when present) and the key, and never touches the network.
- [ ] `RecordingClient(inner)` forwards calls and keeps normalized request/response pairs;
      `.recording(models=..., settings=...)` returns an `LlmRecording`; embedding vectors are
      rounded to 6 decimals on save; `load_recording(save_recording(x)) == x`. Tested.
- [ ] `replay_environment(recording)` sets `MODEL_FAST/MID/DEEP/EMBED` to the recorded ids (unset
      tiers left alone), sets test budget caps (`DAILY_BUDGET_USD`, `TOTAL_BUDGET_USD`,
      `RUN_BUDGET_USD`, `MAX_CALL_COST_USD`) high enough for the recording, clears the
      `get_settings` cache, and restores everything on exit (also after an exception). A test
      proves replay passes with no `.env` (cwd = tmp dir, `NEBIUS_*` unset) and with a different
      `MODEL_FAST` in the environment.
- [ ] Under `client_override(ReplayClient(...))` + `replay_environment`, `llm.complete_json` and
      `llm.embed` return the recorded values and still write one `llm_calls` row per attempt
      (FakeSession test); a planted miss raises `LlmReplayMismatch`.
- [ ] `scripts/record_llm_fixtures.py`: without `--yes` prints a plan (documents per client,
      estimated calls and cost) and exits 0 without calling anything. With `--yes` it refuses unless
      the DB is at head 0005 and both budget caps are set. It replays the sensor fixtures through
      `get_sensor` for every client spec plus `tests/fixtures/web/*.html` (as `website` documents via
      `html_to_text` and `evidence_document_from_sensor`), loads the concepts, and calls
      `radar.ledger.build_evidence` under `client_override(RecordingClient(real))`. It writes
      `tests/fixtures/llm/ledger/<client>.json` (and `web.json`) after `smoke_llm.redact`, and
      refuses to write if a secret, email or phone survives. Tested offline with a stubbed
      `build_evidence` and a fake inner client.
- [ ] `tasks.py` gains a `record-llm` passthrough task (test in `tests/scripts/test_tasks.py`).
- [ ] `tests/fixtures/llm/ledger/README.md` documents the format, the key rule ("a prompt or
      max_tokens change invalidates its recordings; re-record, never hand-edit"),
      `replay_environment`, and that recording is an orchestrator-only step.

## Invariants touched
- #8: replay swaps only the client behind `llm.py`; budget guard and `llm_calls` rows still run.
- Secrets/PII: redaction before write, fail-closed; no API key under replay.
- Tests never call real APIs: a miss is an error, never a network fallback.

## Notes
- `complete_json` retries with the validation error appended; those retry bodies are recorded too
  and replay by key like any other.
- The recorder never persists claims or events (it calls `build_evidence`, not
  `process_document`); its only DB writes are `llm_calls` rows.
- Expected spend: about 7 full-text documents x (1 extract + 1 support + up to 8 embeds), well
  under $0.05.
