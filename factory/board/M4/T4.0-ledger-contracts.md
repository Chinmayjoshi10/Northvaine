## Goal
Land every shared shape of M4 so that four wave-1 tickets can build in parallel: migration 0005
and the matching row models, the new settings, the ledger models, the two frozen LLM output
schemas, the `client_override` hook, the replay error, three new invariant rules, and skeletons
for every M4 module. It also owns every existing test that asserts the DDL or the public names it
changes.

## Contract
Exactly the "Frozen contracts" section of `factory/board/M4/PLAN.md`. Implement everything marked
*(impl)* for T4.0 (models, settings, `client_override`, `LlmReplayMismatch`, the output schemas
`ExtractedClaim`/`ExtractedEvent`/`ExtractionOutput`/`SupportVerdict`/`SupportOutput`,
`evidence_document_from_row`, `evidence_document_from_sensor`, `event_fingerprint`, the invariant
rules). Every other name exists with its signature, a docstring stating the behaviour from
PLAN.md, and a `NotImplementedError` body.

Output schemas (frozen; field names may be adjusted only before merge, never after):
- `ExtractedClaim`: `statement: str`, `source_quote: str`, `subject_name: str | None`,
  `subject_country: str | None`, `subject_role: str | None`.
- `ExtractedEvent`: `event_type: str`, `claim_indices: list[int]`, `subject_name: str | None`,
  `date_text: str | None`, `group_hint: str | None`, `slots: list[SlotValue]` (`SlotValue(name: str,
  value: str)`, so the schema has no free-form object), `concept_label: str | None`,
  `concept_hint: str | None`.
- `ExtractionOutput`: `claims: list[ExtractedClaim]` (`maxItems` = 8, a literal matching the
  `extract_max_claims` default; a test asserts they agree), `events: list[ExtractedEvent]` (`maxItems` 8).
- `SupportOutput`: `verdicts: list[SupportVerdict]`, `SupportVerdict(index: int, supported: bool)`.
- No docstrings and no `Field(description=...)` on these models (comments instead); no
  `pattern`, `minLength`, `format`, `const`, `oneOf`.

## Notes
- Before merge, the orchestrator runs PF1b on this branch's two schemas (PLAN.md precondition 5).
  If a keyword is rejected, change the model here, not `llm.build_request`.
- Pydantic emits a class docstring as `description`; keep the output models docstring-free (put
  the explanation in a module comment). Nullable fields render as `anyOf [X, null]` with
  `default: null`, which PF1 accepted.
- `events` currently has no rows anywhere; `fingerprint NOT NULL` without a default is safe because
  the migration refuses to run on a non-empty table.
- Keep `radar/*` imports light: no httpx, no SDK; `brain/replay.py` skeleton must not import openai
  at module level beyond what `llm.py` already allows (check_invariants: SDK only in llm.py, so
  `ReplayClient` must duck-type the SDK objects instead of importing them).
