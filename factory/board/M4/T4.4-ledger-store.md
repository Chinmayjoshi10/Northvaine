## Goal
The only module that touches `claims` in SQL: store every checked claim once, read back only
verified ones (scoped by time and workspace), and store events idempotently, refusing any that
cite an unverified claim.

## Contract
`core/ledger.py` as frozen in PLAN.md: `UnverifiedClaimError`, `save_claims`, `verified_claims`,
`load_concepts`, `ensure_concept`, `set_concept_embedding`, `save_events`, `events_for_clustering`.

## Acceptance criteria
- [ ] `save_claims` inserts every `ClaimCheck` with its status, offset, verifier and meta
      (subject mention included), `ON CONFLICT (fingerprint) DO NOTHING`, and returns fingerprint ->
      id for all of them (existing rows included). A second identical call inserts 0. db test.
- [ ] `verified_claims` reads only the `verified_claims` view. With `as_of`, it excludes claims whose
      document `available_at` is NULL or later than `as_of`. `workspace_id=None` returns only public
      claims; a workspace id returns public plus that workspace's. db test with one verified, one
      `quote_not_found`, one future-dated, and one private claim of another workspace.
- [ ] A direct INSERT with `verified=true` and `quote_offset` NULL, or with `verified=true` and
      `status='unsupported'`, is rejected by the CHECKs (db test).
- [ ] `save_events` raises `UnverifiedClaimError` if any claim id in the batch is not verified (or
      does not exist) and inserts nothing in that call; otherwise inserts with
      `ON CONFLICT (fingerprint) DO NOTHING` and returns fingerprint -> id. Persists
      `available_at`, `description`, `embedding`, `concept_id`, `cluster_id`, `slots`, `details`.
      Saving the same events twice inserts 0 the second time (db test).
- [ ] `load_concepts` returns the 12 seeds; `ensure_concept` is idempotent on (parent_id, label)
      and returns the existing id; `set_concept_embedding` stores a 1024-d vector (db tests).
- [ ] `events_for_clustering(event_type, occurred_from, occurred_to, as_of=None, limit)` returns
      `ClusterCandidate`s (subject key from `slots`, `group_key`, embedding or None). With `as_of`
      it excludes events whose `available_at` is NULL or later (db test with a future event).
      Events with NULL `occurred_on` are included when the window is open-ended (both bounds None).
- [ ] Unit tests with a fake session (`tests/core/test_ledger.py`) cover the SQL parameter shapes
      and the refusal path without a database.
- [ ] `check_invariants` passes (this is the only module with SQL on claims or a `ClaimRow`
      import); `tasks.py db-test` green.

## Invariants touched
- #2: verified-only reads; refusal of unverified claim ids; idempotency means a re-run cannot
  inflate counts.
- Replay (ARCH §11): `as_of` filters on `available_at` with NULL excluded.
- Privacy: workspace scope on the claim read path.

## Notes
- Use `ANY(:ids)` with a uuid array for the verification check inside the same transaction as
  the insert; do not commit inside these functions (the caller owns the transaction).
- Vectors: follow how M2/M3 write `vector` columns (string literal `'[..]'` cast or the pgvector
  adapter already in use); do not add a dependency.
