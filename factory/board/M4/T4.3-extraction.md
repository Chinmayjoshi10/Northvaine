## Goal
Turn a document into proposed claims and events: one fast LLM call for full-text documents, and
pure code for structured records (TED), which need no model at all.

## Contract
`extract.document_event_types`, `extract.extract`, `structured.structured_evidence` as frozen in
PLAN.md; T4.0's `ExtractionOutput` schema is fixed. Drafts are proposals only: they become facts
only after T4.2's checks.

## Acceptance criteria
- [ ] `document_event_types` returns active level-0 concepts minus `extract_excluded_event_types`.
      Test: excluded labels never appear in the rendered prompt.
- [ ] `extract(doc, concepts, run=...)` makes exactly one fast-tier `complete_json` call (prompt
      `evidence_extract.v1`, `extract_max_tokens`). Title, url and text (truncated to
      `extract_max_doc_chars`, with a "truncated" note) are fenced as untrusted; the allowed event
      types and their descriptions are rendered from the concept rows passed in (data, not code).
      It returns at most `extract_max_claims` `ClaimDraft`s (`extracted_by` = the model id from the
      result) plus `EventDraft`s referencing them by index.
- [ ] Code validates every output field: an `event_type` not among the allowed labels (including an
      excluded one) drops that event; dangling or duplicate claim indices are dropped and an event
      left with none is dropped; `subject_country` must be a known ISO2 code (via `core.standards`)
      or becomes None; `subject_role` and `concept_label` must be snake_case or become None;
      `occurred_on = dates.parse_date(date_text)` or None (the LLM never decides a date; grounding
      happens later in T4.5); slots become a `{name: value}` dict with non-snake names dropped.
      Tested with a fake client whose reply contains each kind of bad value.
- [ ] An injected-instruction document (`tests/fixtures/web/home.html` text) is passed only inside
      the fence; a test asserts the fence markers wrap it and that none of its text appears outside.
- [ ] `structured_evidence(doc)` returns None unless `doc.source_name` maps to `structured` in
      `evidence_source_rules` and `meta.schema_ver == 1`. Otherwise it builds, from `doc.meta` and
      the D39 rendering, one `ClaimDraft` per fact (`extracted_by='code'`) whose `source_quote` is
      one whole line of `doc.text`, with a generic templated statement; and EventDrafts:
      `tender_published` (subject = buyer, occurred_on = publication date) or `contract_awarded`
      (one per winner, occurred_on = winner decision date, else publication date). Slots carry cpv
      codes, buyer/winner names and countries, deadlines, value; `group_key = doc.group_key`.
- [ ] Over every recorded TED fixture, every structured draft's `source_quote` is exactly one line
      of the document text (`quote in doc.text.split("\n")`, the stand-in for T4.2's structured
      `find_quote` until it merges), every event's claim indices are valid, and no LLM is called
      (client_override with a client that fails on any call).
- [ ] The prompt contains no industry words, and no client value appears as a literal in
      `northvaine/radar/` (the T3.6 AST check stays green).

## Invariants touched
- #1: event types are rows passed in; TED field handling is generic (no CPV or country literals).
- #2: drafts carry quotes for the code check; the extractor never sets `verified`.
- #7: all document content fenced; extractor output is validated, never trusted.
- #8: one `complete_json` call; tests use `client_override`.

## Notes
- TED meta field names come from `parse_notice` (schema_ver 1); read them, do not re-parse the
  rendered text. Lines rendered by `render_notice_text` are the only acceptable quotes.
- Multi-language buyer names render on one line per language; quote the line, not a fragment.
