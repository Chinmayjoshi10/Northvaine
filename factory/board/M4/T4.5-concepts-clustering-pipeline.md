## Goal
Wire the ledger together: from one document to stored verified claims and grounded, deduplicated,
concept-tagged events, with every LLM call in the right order and nothing built from unverified
material.

## Contract
`radar/concepts.py` (`cosine`, `assign_concept`, `assign_cluster`, `seed_concept_embeddings`) and
`radar/ledger.py` (`ground_event`, `describe_event`, `build_evidence`, `process_document`) as
frozen in PLAN.md. Do not change T4.0's implemented `evidence_document_from_*` or
`event_fingerprint`.

## Acceptance criteria
- [ ] `assign_concept` (pure): the level-0 parent comes from `event_type`. With an embedding it
      picks the nearest active or proposed child of that parent at cosine >=
      `concept_match_min_cosine`; otherwise it returns a new `proposed` child (label = the draft's
      `concept_label`, snake_case; description = `concept_hint` or a generic template; embedding =
      the event's) or the parent itself when there is no label. With no embedding it returns the
      parent. Tested with injected vectors.
- [ ] `assign_cluster` (pure): with embeddings, returns an existing `cluster_id` when event_type
      matches, subject key (casefolded) or group_key matches, occurred_on is within
      `event_cluster_window_days` (both NULL matches only with the same group_key), and cosine >=
      `event_cluster_min_cosine`. Without an embedding on either side, it matches deterministically on
      (event_type, group_key) or (event_type, subject key, window). Otherwise a new uuid. Tested,
      including two TED versions of one procedure sharing a cluster.
- [ ] `ground_event(draft, checks)` keeps only the draft's verified claim indices (None if none
      remain); keeps `occurred_on` only if `date_text` is in some verified quote of the event
      (`quote_contains`), else None; keeps the subject only if its name is in a verified quote
      (else subject None); keeps the country only if its ISO2 code or `iso2_to_name` is in a verified
      quote; drops every string slot value not in a verified quote. Test with an extractor reply
      whose date, subject, country and one slot are absent from the quotes.
- [ ] `describe_event` is deterministic code over event_type, the grounded subject name and the
      verified statements; no LLM text is used verbatim except verified statements.
- [ ] `build_evidence`: a lead document gives `LedgerResult` with `eligibility.kind=lead`, no checks
      and ZERO LLM calls. A structured document gives `structured_evidence` +
      `verify_claims(mode=structured, support=False)`, no LLM and no embedding, concept = the level-0
      seed. A full-text document: extract, then verify, then per event ground, describe, embed (one
      call), assign concept and cluster, `available_at = doc.available_at`, and
      `event_fingerprint`. `llm_calls` counts the calls made. Each path tested with fake clients.
- [ ] A pipeline test with a recording fake client asserts the order per document: the extract call
      precedes any support call, every quote in the support request passed `find_quote`, and embed
      calls come only after the support call and only for events with a verified claim.
- [ ] `seed_concept_embeddings(session, run=...)` embeds the level-0 concepts whose embedding is
      NULL and is idempotent (a second call makes no embed call).
- [ ] `process_document(session, doc, run=..., as_of=None)` refuses a document with `workspace_id`
      set (ValueError, parked), loads concepts and `events_for_clustering(as_of=as_of or
      doc.available_at)`, builds, then persists through `core/ledger` only: `save_claims`,
      `ensure_concept` for new concepts, `save_events`. db test on one TED document and one synthetic
      web document with a fake client; running `process_document` twice on the same document leaves
      the claims and events row counts unchanged.
- [ ] Same code for all three client specs: no client value is a literal (T3.6 generality check
      stays green); `check_invariants` passes (no SQL here).
