## Goal
The money guard. Four caps checked before every model call, a hard stop that never silently
degrades, and one `llm_calls` row per attempt so every cent spent - including on retries - is
visible. Under a $1 lifetime budget this is the ticket that decides whether the project can afford
milestones 3 to 5.

## Contract
Implements the T2.0 skeletons: `RunContext`, `check_budget(...)`, `record_call(...)`.
`ConfigError` is **imported from `northvaine/core/settings.py`**, never redefined in
`brain/errors.py`. `BudgetExceeded(kind, cap, spent, would_spend)` comes from `brain/errors.py`.
`LlmCallRow` and `BudgetKind` come from `core/models.py`.

## Acceptance criteria
- [ ] `check_budget(...)` is called **before** every model call with an upper-bound cost estimate
      (prompt tokens plus `max_output_tokens`, at the model's price from `pricing.json`) and
      enforces four caps in this order: per-call `max_call_cost_usd`, per-run `run_budget_usd` from
      the `RunContext`, per-day `daily_budget_usd`, lifetime `total_budget_usd`. It raises
      `BudgetExceeded` naming the cap, the limit, the amount already spent and the amount the call
      would add. It **never** trims the request, downgrades the model or returns a partial result.
      A test asserts the order by tripping each cap in turn.
- [ ] If `daily_budget_usd` or `total_budget_usd` is unset, `check_budget` raises `ConfigError`
      naming the variable - calls refuse to run until the founder sets both (DECISIONS 2026-10-03).
      A test proves each variable is named in its own message.
- [ ] The **daily** cap is summed from `llm_calls` for the current **UTC** day bucketed by
      `workspace_id` (NULL is its own bucket, which is what onboarding and smoke calls use); the
      **lifetime** cap is summed across all rows with no filter. Both are single SQL aggregates
      using the indexes T2.1a added. Tests prove the bucketing and the UTC day boundary (a row at
      23:59:59Z and one at 00:00:01Z fall in different days).
- [ ] `record_call(...)` writes **exactly one** `llm_calls` row per attempt - successes, transport
      failures, timeouts and invalid-output retries alike - with model, purpose, `run_id`,
      `prompt_version`, token counts, `cost_usd` computed from `pricing.json`, `ok`, `latency_ms`
      and a truncated `error`. A failed call with no usage reported records `cost_usd = 0` and
      `ok = false`, **never a guess**. Tests cover the success row and the three failure rows.
- [ ] `RunContext` accumulates spend in memory across the calls of one run and exposes `spent`.
      A test shows three cheap calls inside one run tripping the run cap on the third while the
      daily and lifetime sums are still far below their caps.
- [ ] The API key, the database URL and any secret appear in no `BudgetExceeded` or `ConfigError`
      message and in no `llm_calls` row. A test asserts this.
- [ ] Unit tests in `tests/brain/test_budget.py` use a fake session/executor and make **no** network
      and **no** database calls. The `db`-marked tests in `tests/db/test_budget_db.py` prove the
      real SQL aggregates and the real insert against `TEST_DATABASE_URL` and are deselected from
      the gate.
- [ ] Two known limitations are documented in the module docstring:
      (a) check-then-call is **not atomic**, so M2 runs model calls serially; concurrent
      reservations are parked in `docs/LATER.md`.
      (b) the lifetime cap is summed **per database**, so spend recorded against
      `TEST_DATABASE_URL` and spend recorded against the production database are two independent
      "lifetimes" of the same single dollar, and any raw probe call made outside `brain/llm.py`
      writes no row and is invisible to both.
- [ ] `uv run python scripts/gate.py` passes.

## Invariants touched
- **CLAUDE.md #8** - per-call and per-run budgets, and a row in `llm_calls` for every call. This
  ticket is the enforcement half of that rule.
- **No secrets in logs or rows.**
- **Facts, not guesses**: a failed call with no usage records 0, not an estimate.

## Notes
- Depends on T2.1a because the four new columns and the `created_at` indexes must exist before the
  ledger writes them and the aggregates rely on them.
- Keep all money arithmetic in `Decimal`. `cost_usd` is `numeric(10,6)` in the schema; round
  explicitly and consistently so the sums match what the smoke script prints.
- `RUN_BUDGET_USD` and `MAX_CALL_COST_USD` **do** have defaults (T2.0) - only the daily and
  lifetime caps refuse to default, because those are the founder's wallet.
