## Goal
Land every shared shape of M3 so that wave 1 and wave 2 can build in parallel: the sensor
models and protocol, migration 0004 and the matching `DocumentRow`, the new settings, the ISO
3166 country table, and the three pure pieces that two tickets would otherwise both need
(`dates.parse_date`/`parse_datetime`, `ted.build_request`, `tavily.build_search_request`).
Everything else is a frozen skeleton.

## Contract
Exactly the "Frozen contracts", "Canonical TED request" and "Canonical Tavily search request"
sections of `factory/board/M3/PLAN.md`. This ticket implements everything marked *(impl)* for
T3.0a there; all other names exist with docstrings and `NotImplementedError` bodies.
`sensors/replay.py` is T3.0b's, not this ticket's.

## Acceptance criteria
- [ ] `northvaine/sensors/base.py` implements `DateFlag`, `SensorQuery`, `SensorDocument`,
      `SensorResult` (incl. `enumerable`), the runtime-checkable `Sensor` protocol, the error
      classes (`SensorError`, `FetchBlocked`, `RobotsDisallowed`, `SensorRateLimited(retry_after)`,
      `ReplayUnsupported`, `LeakageError`) and `content_hash`. Proven in `tests/sensors/test_contracts.py`.
- [ ] `SensorQuery` validation is proven by tests: bad code scheme, non-ISO2 country, non-ISO639-1
      language, `published_from > published_to`, and `max_results` outside 1..`sensor_max_results`
      are each rejected.
- [ ] `SensorDocument` availability is proven by named tests: naive `fetched_at`/`available_at`
      rejected; tier company/reported with `available_at > fetched_at` rejected; tier official
      with `available_at` set and `published_on` None rejected; tier official with
      `available_at` earlier than 00:00 UTC of `published_on + 1 day` rejected;
      **`test_ted_notice_fetched_on_its_publication_day_is_valid`** (published_on = D,
      fetched_at = D 14:00 UTC, available_at = D+1 00:00 UTC) accepted; `available_at=None`
      accepted for any tier; `date_flags` accepts only `DateFlag` values.
- [ ] `dates.parse_date` and `dates.parse_datetime` are implemented and proven in
      `tests/sensors/test_dates_parse.py` on every shape in the research notes: `2026-04-01+02:00`
      (-> date 2026-04-01 as written), `2026-06-17T15:00:00+03:00`, ISO with `Z`, plain
      `2026-04-01`, RFC 1123 `Tue, 11 Mar 2025 17:00:00 GMT`; `None`, `""` and garbage return
      None without raising; `parse_datetime` never returns a naive datetime.
- [ ] `core/standards.py` gains `iso2_to_iso3` and `iso2_to_name`, backed by
      `northvaine/core/iso3166.csv` (all ISO 3166-1 countries). Proven in
      `tests/core/test_standards_iso.py` (`DE->DEU`, `GB->GBR`, `GB->'united kingdom'`,
      unknown -> KeyError, every row has a unique alpha-2 and alpha-3).
- [ ] `ted.TED_SAFE_FIELDS`, `ted.TED_KIND_TO_NOTICE_TYPES`, `ted.TED_MAX_LIMIT` and
      `ted.build_request` follow PLAN.md's canonical TED request. Proven in
      `tests/sensors/test_request_builders.py`: clause order; `=` for one value and `IN (a b)`
      for several; ISO2 -> alpha-3; date format `yyyyMMdd`; with `as_of` the upper bound is
      `min(published_to, as_of UTC date - ted_availability_lag_days)`; `limit` capped at 250;
      non-cpv codes and `text` ignored; no mappable kind -> ValueError; and
      **no field in `TED_SAFE_FIELDS` matches `email|tel|fax|person|contact-point|ubo|internet-address`**.
- [ ] `tavily.build_search_request` follows PLAN.md's canonical Tavily request and returns
      `(body, notes)`. Proven in the same test file: `include_published_date` true,
      `include_raw_content` "text", `max_results` capped at 20, `start_date`/`end_date` from the
      range, `country` only with exactly one country (as `iso2_to_name`), otherwise omitted with
      a note; `days`, `auto_parameters` and any key never appear in the body; `text=None` -> ValueError.
- [ ] Skeleton modules `fetch.py`, `html_text.py`, `website.py`, `procedures.py`, `registry.py`,
      `core/documents.py`, plus the not-yet-implemented names in `dates.py`, `ted.py` and
      `tavily.py`, expose the PLAN.md signatures. `tests/sensors/test_contracts.py` asserts names,
      parameters, async-ness, and that importing every `northvaine.sensors` module created here
      does no network I/O and needs no env vars. It **never** asserts that a stub raises.
- [ ] Migration `0004_sensor_documents` adds `documents.external_id text`,
      `documents.group_key text`, `documents.meta jsonb NOT NULL DEFAULT '{}'`, indexes
      `documents_group_key (source_id, group_key)`, `documents_external_id (source_id, external_id)`,
      `documents_available_at (available_at)`, and `sources_name_key UNIQUE (name)`, with an
      exact-reverse downgrade. `schema.sql` matches (header names migrations 0001-0004);
      `DocumentRow` gains `external_id`, `group_key`, `meta`. Proven by
      `tests/core/test_migration_0004_offline.py`, `tests/core/test_schema_consistency.py`, and
      any updated head/DDL assertion in the owned M1/M2 test files.
- [ ] Settings gain every M3 setting in PLAN.md with those defaults (`tavily_api_key` is a
      `SecretStr | None`; `ted_availability_lag_days >= 1` validated); `.env.example` lists
      `TAVILY_API_KEY` by name only. No setting reads the network at import. Proven in
      `tests/core/test_settings.py`.
- [ ] `httpx` moves from the dev group to runtime dependencies; `uv.lock` updated; no other new
      runtime dependency.
- [ ] `tests/fixtures/sensors/README.md` documents the `RecordedExchange` file layout
      (`tests/fixtures/sensors/<sensor>/<client>_<n>.json`), the redaction rules, and the TED
      attribution line.
- [ ] Mechanical check (FACTORY §2 rule 9): on this branch `uv run pytest -m "not live and not db"`
      has zero failures and every test file changed is in `writes`. `uv run python scripts/gate.py`
      passes; `uv run python scripts/tasks.py db-test` passes when `TEST_DATABASE_URL` is set.
