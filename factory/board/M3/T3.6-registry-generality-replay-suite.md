## Goal
Prove the M3 promise end to end: the same code serves very different clients (D33), and no
sensor can leak the future into a replay.

## Contract
From PLAN.md: `SENSOR_NAMES`, `get_sensor(name, *, client=None, settings=None) -> Sensor`.

## Acceptance criteria
- [ ] `registry.py`: `SENSOR_NAMES == ("ted", "tavily", "website")`; `get_sensor` returns
      instances satisfying the runtime-checkable `Sensor` protocol and passes `client`/`settings`
      through; an unknown name raises `KeyError` listing the known names. Proven in
      `test_registry.py`.
- [ ] `test_generality.py` runs every sample-client spec through one parametrized test with an
      identical loop body (`get_sensor(name, client=replay_client).search(q)` for each listed
      sensor and query), no per-client branches. It asserts each client yields >= 1 document per
      listed sensor; every document has `content_hash` and tz-aware `fetched_at`; TED documents
      have `available_at` and `group_key`; Tavily documents have `available_at == fetched_at`.
- [ ] `test_generality.py` also asserts that no client-spec value is a **string constant** in any
      `northvaine/**/*.py` file, using `ast` (not substring search): it checks full CPV codes
      (with and without the `cpv:` prefix) and whole multi-word query texts. ISO country and
      language codes, and single generic words, are excluded; the exclusion list is documented in
      the test.
- [ ] `test_replay_leakage.py`: for an `as_of` between two recorded TED notices' availability, the
      TED sensor returns no document with `available_at > as_of`, and `assert_available` passes on
      its output; Tavily and website raise `ReplayUnsupported`; `assert_available` raises
      `LeakageError` on a hand-built leaking list; every `SensorResult` reports `enumerable`
      matching its sensor class (ted True; tavily, website False), so recall can be claimed only
      for enumerable sensors (D30/D41).
- [ ] `uv run python scripts/gate.py` passes on main after the wave merges.
