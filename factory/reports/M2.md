## Root cause: the wave-0 fix moved the DDL but not the tests that assert the old DDL

Commit `f977f86` correctly fixed run 1's defect by moving `schema.sql` and
`migrations/versions/0003_*.py` into T2.0's `writes:`. That removed the `LlmCallRow` orphan-field
failure. But sizing the vector columns to `vector(1024)` and adding head 0003 breaks three tests
that assert the *old* state, and **T2.0 owns none of them**:

```
FAILED tests/core/test_migration_0002_offline.py::test_offline_upgrade_has_no_sized_vector
FAILED tests/core/test_migration_0002_offline.py::test_schema_sql_is_the_v2_end_state
FAILED tests/core/test_schema_consistency.py::test_no_vector_column_has_a_dimension
3 failed, 281 passed, 15 deselected in 14.44s
GATE FAILED at step: unit tests
```

```
AssertionError: schema.sql: {'document_chunks.embedding': 'vector(1024)',
 'event_concepts.embedding': 'vector(1024)', 'theses.embedding': 'vector(1024)'}
assert {'vector(1024)'} == {'vector'}
```

Ownership of the three files:

| Failing test file | Owned by |
|---|---|
| `tests/core/test_schema_consistency.py` | **T2.1a — wave 1**, i.e. after T2.0 |
| `tests/core/test_migration_0002_offline.py` | **M1's T1.4. No M2 ticket owns it at all.** |

So T2.0's final acceptance criterion — "`uv run python scripts/gate.py` passes" — is again
unsatisfiable within its own write scope, and this time one of the three blocking files has no M2
owner in any wave. The builder behaved correctly: it stayed inside `writes:`, reported the three
failures precisely, attributed them, and blocked rather than reaching outside its scope or
weakening a test. **The defect is in the board, not the build.**

## Follow-ups

**Blocking, in order.** The whole milestone is one amendment away from proceeding; do not re-plan it.

1. **Add the three test files to T2.0's `writes:`** — `tests/core/test_schema_consistency.py` and
   `tests/core/test_migration_0002_offline.py` — and remove the first from T2.1a's `writes:`.
   The rule that both runs violated is simple: *whoever changes the DDL owns every test that
   asserts the DDL.* `test_migration_0002_offline.py` additionally needs a decision about what it
   should assert once 0003 exists — `test_schema_sql_is_the_v2_end_state` is by name a statement
   that `schema.sql` stops at v2, which is no longer true; it should become a 0003 end-state
   assertion, or be superseded by T2.1a's `test_migration_0003_offline.py`.
2. **Restate T2.1a.** With the DDL and now its tests in T2.0, several of T2.1a's acceptance
   criteria ("Migration 0003 sets...") describe work it no longer owns. Narrow it to the live
   schema test and the EMBED_DIM agreement test, or fold it into T2.0 entirely.
3. **Rerun T2.0 by rebasing `de30a36`, not from scratch.** The contract work is good. Discarding
   +1109 lines over a board defect for the second time would be pure waste.
4. **Then run waves 1–5 unchanged.** No other ticket needs amending; none was started and their
   write sets stay disjoint.
5. **Apply 0003 to the production Neon branch** once T2.0 lands — founder's explicit go-ahead,

**Process, for the retro:**

9. **Prune the orphan worktrees.** Nine `worktree-wf_*` branches now exist across M1 and M2 runs;
