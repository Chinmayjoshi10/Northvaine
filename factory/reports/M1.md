### T1.2 blocker (planning defect, not a code defect)

The T1.0 test `tests/core/test_contracts.py::test_stubs_raise_not_implemented` asserts
`db.get_engine()` raises `NotImplementedError`. T1.2 exists to implement that function. With no
URL, `get_engine()` now raises `ConfigError`, as T1.2's acceptance criteria require.
`tests/core/test_contracts.py` is not in T1.2's `writes`, so the builder could not fix it.

I reproduced this in the T1.2 worktree (`.claude/worktrees/wf_db8f9938-eb3-6`, uncommitted
changes to `northvaine/core/db.py`, plus new `tests/core/test_db.py` and
`tests/db/test_db_live.py`):

- **Default run:** 1 failed, 100 passed. The only failure is that test.
- **Builder's run, with that test deselected:** 100 passed, 1 skipped. Invariants and ruff are
  clean.

The same test also asserts `queue.backoff_delay(1)` raises `NotImplementedError`, so **T1.7 will
hit the same block**.

Recommended fix: a contract-maintenance change to `tests/core/test_contracts.py`, made by the
orchestrator or integrator, or by adding the file to T1.2's and T1.7's `writes`. Each
implementing ticket removes its own stub assertion. Frozen signatures do not change. After that,
T1.2 can be re-reviewed, gated and merged from the existing worktree, and waves 2 to 4 can go
ahead.
