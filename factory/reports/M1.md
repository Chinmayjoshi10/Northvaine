  PEP 735 dev group and only the substrate dependencies. Typed `Settings` with

  migrations, and db tests deselected from the gate.
- **T1.6 Row and enum models.** Pydantic models that mirror schema v2.
- **T1.7 Jobs queue.** `enqueue`, a SKIP LOCKED claim, `heartbeat`/`complete`/`fail` that
  check job ownership, capped backoff, `requeue_stale` and `run_worker`. The db-test
  failure in the last report was a test bug: an `await` inside a generator passed to
  `all()`. The fix is in 63134c1.

### T1.8: why it is blocked, and why it can now be unblocked

The build run reported T1.8 as `blocked`. Its code was finished and its gate was green
(245 passed, 15 deselected, lint clean). Its last criterion is milestone sign-off: db-test
must pass against the founder's TEST_DATABASE_URL. The builder's worktree had no `.env`, so
its 3 live tests were skipped and had never run against a real database.

I ran them during this verification. From the T1.8 worktree, TEST_DATABASE_URL came from
main's `.env` and was passed as an environment variable. No file was copied, and the value
was not printed.

- `pytest -m db tests/db/test_schema_live.py`: **3 passed** in 150 s.
  - `test_tables_columns_and_nullability_equal_schema_sql`
  - `test_patterns_view_exists`
  - `test_vector_columns_are_dimensionless`
- `uv run python scripts/tasks.py db-test`: **15 passed, 245 deselected in 719.30 s, exit
  0.** That covers the db live, migrations, queue and schema-live tests.
- Server: Neon Postgres 18.6. Version 18.6 was recorded by the previous Neon db-test, and
  `db-check` reports `18.6 (180006)`.
- Event loop: `ProactorEventLoop`, the Windows default, on Python 3.12.13.
- Library versions: pytest-asyncio 1.4.0, asyncpg 0.31.0, SQLAlchemy 2.1.2.
- Loop scope: function-scoped for both tests and fixtures.

**Review of the T1.8 diff:**
- Scope: only the four `writes` paths changed.
- Network: there is none in the default tests. Live tests are marked `db`.
- Tests are not weakened. The adversarial cases each assert the exact problem they expect,
  not just that something failed.
- No blocking findings. One nit: `test_every_check_in_list_has_a_matching_enum` uses
  `getattr(m, model_name(table))` with no default. A missing model would raise an
  `AttributeError` instead of a clear assertion. `test_row_models_match_tables` already
  reports that case cleanly.

**To unblock:**
1. The integrator merges 5833384 into main.
2. Run `uv run python scripts/gate.py` on main.
3. Rerun db-test on main.
4. Set T1.8 to `done`. Its ticket file still says `status: approved`.
